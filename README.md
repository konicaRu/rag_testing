# rag_testing

## Актуальное состояние Ragas — 20 октября 2026

Эта запись уточняет текущий этап; прежние планы и результаты ниже сохранены как история. Источник экспериментальных результатов — handoff пользователя и сохранённые ячейки Notebook; при обновлении памяти ячейки и модели не запускались.

Проект готовит независимую оценку RAG А3 с помощью Golden Dataset. Основной текущий подход — штатные Knowledge Graph, трансформации, сценарии и синтезаторы Ragas, затем ручное утверждение и оценка RAG. Классификатор документов не заменяет эти механизмы без отдельного обоснования.

Работа продолжается в `golden_dataset_project/notebooks/02_ragas_experiment.ipynb` через JupyterLab и kernel **A3 Golden Dataset** существующего `.venv`. Python 3.11.9, Ragas 0.4.3, langchain-community 0.4.1; остальные точные версии — в [журнале эксперимента](docs/RAGAS_EXPERIMENT_2026-10-20.md). Пакеты при обновлении памяти не устанавливались.

Проверенные в опыте локальные модели LM Studio: `qwen2.5-14b-instruct-1m` и `text-embedding-nomic-embed-text-v1.5` (768), endpoint `http://127.0.0.1:1234/v1`. Рабочий структурированный клиент: Instructor MD_JSON → InstructorLLM. Проверка одного экстрактора не гарантирует работу всего Ragas.

Корпус имеет независимый локальный `corpus_snapshot/`: 200 файлов, 200/200 совпадений SHA-256 оригиналов и копий, 0 ошибок при создании, 5 446 767 байт. Snapshot, manifest и отчёт не публикуются. Путь snapshot задан отдельно в config.yaml, исходный rag_a3 не изменяется.

На искусственных текстах проверены граф, ключевые фразы и связи; реальные 12 документов уже прочитаны и измерены в сохранённом шаге 18. Следующее действие — анализ размеров и решение о разбиении, затем граф на этой выборке. Кандидатные вопросы, утверждённый Golden Dataset и оценка RAG ещё не созданы.

Бизнес-словарь из первого Notebook остаётся для анализа покрытия и качества, пока не ограничивает входные документы. Ранее описанный пилот классификации 15–20 документов ниже — история, а не текущая очередь.

## Как будем работать

Основной интерфейс — уже открытый пользователем Jupyter Notebook через JupyterLab. VS Code остаётся возможным интерфейсом. Код предоставляется в чате для ручного копирования: одна логическая операция — одна ячейка, комментарии на русском, объяснение для начинающего. После каждой ячейки ждём результата пользователя. Не переписываем Notebook автоматически без явной просьбы.

Поток: тема → автоматическая подборка документов → проверка источников → генерация вопросов и ответов → утверждение эталона → запросы к RAG → расчёт метрик.

Текущий пилот — оценка релевантности 15–20 документов сущностям `active_subscription`, `system_subscription`, `notification`. Упоминание не равно содержательному знанию; соответствие бизнес-определению оценивается отдельно. Тема «Партнёр» была первоначальным планом и не является текущим первым шагом.
